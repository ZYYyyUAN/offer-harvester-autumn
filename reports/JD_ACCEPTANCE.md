## 接口契约

统一入口为 `GET /api/jd` 和 `/api/jd/[...path]`，没有另建一套模型调用中心。

| 路径（/api/jd 下） | 行为 |
| --- | --- |
| GET sources/:id、snapshots/:id | 来源、历史、提取与人工修订 |
| POST sources/:id/archive | 首次归档、补录、带原因的新修订 |
| POST snapshots/:id/extract、ignore | 创建 AI 提取任务、切换统计忽略状态 |
| POST extractions/:id/activate、edit | 有效版本切换、追加人工修订 |
| POST resumes/:id/parse、texts/:id/confirm | 简历解析及人工正文核对 |
| GET/POST gaps | 历史报告或创建冻结输入的差距任务 |
| POST suggestions/:id、:id/task、:id/result | 确认状态、幂等任务、手动修改稿关联 |

写入携带 version；AI 仍通过 `/api/ai/jobs/:id/run|retry|cancel` 执行。跨所有者资源返回 404；过期版本或过期样本摘要返回 409。普通 records PATCH 不能改写专用归档记录。

## 真实千问结果与限制

`reports/jd-regression.json` 保存 30 组标注 JD 的逐项预期、实际输出、差异、模型、Token、耗时及三组独立 A/B/C 简历/事实测试。全为合成数据，没有读取真实求职资料。29 组非空 JD 真实调用；空 JD 验证 422，不进行无意义的付费调用。

- 提取模型 `qwen3.8-max`，提示 `jd-requirements-v2`；在此固定样本上 Precision/Recall/F1 均为 1.00，正式引用无效数 0，Schema 通过率 100%。采用要求级一对一匹配，同时检查优先级、否定和可选关系，不能靠重复关键词提高得分。
- 提取 Token 合计 21,208；P50 5,014ms，P95 6,415ms；首轮成功率 100%。此批无重试样本，因此重试后成功率不作实测结论。
- 差距提示最终为 `resume-gap-v4`，A/B/C 三组均经正式 Worker 任务管线调用并通过；人工复核建议未添加候选人事实，A/B 个人证据引用覆盖率 100%。后续仅重跑受提示改动影响的三组差距场景和一条提取种子，保留先前未变更的 30 组提取结果及运行时间，报告 providerCalls=4 指该补充批次。
- 修复过程：v1 提取存在重复 key/优先级问题；早期差距输出存在无效分类和引用；v3 有一条“使用 Java”被夸大为“熟练掌握、独立设计”，人工验收拒绝。v4 限制为修改方向和提问，经历表达若非引用个人原文的逐字摘录则服务端拒绝，未降低引用标准。
- `reports/jd-document.json`：有效合成 PDF 经 `qwen-doc-turbo` 真实解析成功，输出与合成正文相符；DOCX 的本地解析经过主流程测试。未执行旧二进制 DOC 的真实供应商解析验收。

这些是固定合成集的结果，不是对任意 JD 准确率或录用效果的保证；自动数字检测不能代替人工语义复核。
