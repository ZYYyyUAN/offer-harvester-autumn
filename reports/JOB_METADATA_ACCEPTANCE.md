# 公司分类与求职渠道自动预填：验收记录

开发基线：5b611aaf2632cfbaeb3bb0060b592ca1e8401c49；发布前线上 v41，owner-only 已由 Sites 返回的访问策略核对。本文区分已执行证据与生产待验收事项。

## 数据与行为

- `lib/job-metadata.ts` / `lib/job-metadata-store.ts`：公司性质、多标签、岗位用工形式、当前链接平台、发现来源、计划渠道、实际渠道与内推分开。发现来源与提交渠道独立服务端枚举；实际渠道只读 `actualSubmission.channel`。不从 spread、英文公司名、银行或上市状态猜测性质/内推。
- 确定性域名/路径规则、已确认公司主体候选、OCR 原文线索在原有流程中预填；粘贴或点击识别渠道不调用模型。明确 OCR 平台标识由规则处理。普通网页没有独立可核对正文时显示 AI 待核实，不伪装页面核实事实。
- 人工改选、清空、拒绝、上下文失效均保留；同公司更换链接保留人工发现来源和已确认公司资料，迟到响应不能覆盖新公司/人工输入。
- `lib/job-capture-save.ts`：明确字段优先于持久草稿，草稿优先于原提取；空值保留。确认和封存草稿同次提交。收藏转换使用专用原子接口及稳定身份；准备中不会因为推荐渠道改变阶段。
- 既有阶段、检查项、最终简历、表单、任务与飞书回写复用 `application-submission.ts`。投递更新、首次归档及事件同次提交；明确渠道可以留未知。后期分类和渠道通过 `submission_metadata_revisions` 追加，原 JD 正文和哈希不变。
- 统计使用真实投递身份、历史快照及明确标记的补录。计划渠道不参与实际渠道统计，未知单列，标签不增加分母，小样本沿用个人设置门槛。
- JSON 写入 v5，继续读取 v3/v4；CSV 保留 dataJson。新记录、引用、人工修订、历史、删除恢复和 owner 隔离均校验。飞书旧字段缺失不清空新增 metadata，不默认新增远程字段。
- `0007_giant_red_shift.sql` 仅增加转换身份、投递修订及非空信用代码唯一索引；历史分类迁移需要显式预览和确认，不自动执行。
